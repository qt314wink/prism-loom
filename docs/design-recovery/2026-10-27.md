## Repository-specific records

### D17 — Wildfire Iridescent: token-to-renderer integration with honest material semantics

**Use when:** When working on Wildfire's monorepo, CSS-to-GLSL bindings, Storybook specimens, thin-film direction, or shared renderer adapters.

[Recovered intent] Wildfire joins an iridescent UI language, renderer package, tokens, Storybook, playground/web consumers, and visual testing. The earlier bridge document explicitly tries to make designer-facing tokens reach shader execution.

[Observed implementation] The sampled useTokenUniforms hook resolves numeric animation speed and film-thickness variables once in an effect, applying them only when a material has the corresponding uniform. The sampled AbaloneShader declares time, speed, and mouse, and generates phased RGB sinusoids on a plane. It does not consume the two film-thickness uniforms or model independent camera/light transport.

[Repair resolution — proposed] Preserve the appearance preset under an honest label; do not rewrite it merely to make its old name sound scientific. Add a separate material-backed lane when qualified. Bind each exposed token to its declared consumer and report missing/inactive bindings. Implement theme/config updates deliberately instead of promising a MutationObserver behavior that this hook does not contain.

[Bridge correction] The aspirational bridge's wavelength normalization and /255 hex mapping are not universal physical conversions. Preserve wavelength units or a declared conversion, distinguish sRGB input from linear working color, and record time/angle/space units. Use source hashes and render evidence together.

[Reimagined horizon] A reliable adapter and component showcase where tokens control verified mechanisms, and material appearance remains artistically expressive across consumers.

[Carry-forward test] Sweep each token, observe active uniform changes and rendered influence, toggle themes after mount, freeze time, and separate pointer, view, and light effects. Visual baselines present in a tree are not proof of the latest run.

### D29 — Ocular Fractal Field: playable spatial wonder with preserved canonical state

**Use when:** When recovering Ocular Fractal Field, particle instruments, mandala-to-volume transitions, phase-weaving gameplay, camera choreography, or adaptive rendering.

[Recovered intent] The August 14 design specifies a bird's-eye mandala that descends into a volumetric particle field. The player traces phase targets into luminous threads; intersections trigger authored elemental reactions and build a constellation through play. This is an instrument and short spatial game, not only a particle-count benchmark.

[Architecture] Framework-neutral TypeScript is editable authority; standalone HTML is generated distribution. Simulation, camera director, phase-weaving game, orchestration, browser input, GPU renderer, audio, haptics, accessibility, replay, and telemetry have distinct ownership. Quality may adapt without changing play results.

[Design DNA] Preserve continuous pattern morphing, Mandala Axial and Bismuth Hopper Grid families, interruptible camera itinerary with deliberate rejoin, spectral depth, synthesized audio recipes, and equivalent non-gyro/keyboard/reduced-motion completion.

[Observed boundary] The current README confirms the authority direction; the detailed design is retrieved from prism-loom attachments and labels its source/approval state. This pass did not run the simulation or establish full production completeness. A numeric particle target must remain separate from measured device capability.

[Repair resolution — proposed] Carry the full game/experience forward while testing deterministic core, semantic input, camera authority, and renderer qualification separately. Do not make sensory intensity a hidden difficulty change. Keep replay identity independent of noncanonical performance telemetry.

[Reimagined horizon] A replayable, teachable spatial instrument whose authored interactions become shareable constellations, controlled films, and portfolio proof.

[Carry-forward test] The same inputs yield the same gameplay events/state across render tiers; manual camera interruption is responsive; low-motion/muted users can complete the same task; exported replay is traceable.

## Practical continuation contract

1. Re-read current repository instructions and source before implementation. The baseline above identifies this publication, not a permanent execution HEAD.
2. Retain the full design horizon separately from the current demonstrator. Name what the demonstrator preserves, approximates, defers, or cannot prove.
3. Map tokens and controls to actual consumers with explicit units, ownership, accessible alternatives, and observable effect.
4. Complete the relevant interaction/error/cancellation states before promoting a reusable component.
5. Pair source/runtime checks with human correspondence review against the actual visual inspiration.
6. Keep proposed repairs unexecuted until a later implementation records its own revision, checks, and evidence.
